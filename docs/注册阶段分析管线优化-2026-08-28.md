# 注册阶段分析管线优化（2026-08-28）

## 问题原因

旧管线只把触发监控的“同意注册公告”放进证据包。该公告本身通常只说明批复事实，不包含募集规模上限、最新总股本和行情数据；同时提示词要求模型只使用给定证据，因此邮件只能写“数据不足、无法计算”。这不是模型措辞问题，而是证据构建阶段缺少数据补全和发送前完整性校验。

此外，旧分类规则会把“募集说明书（注册稿）”或“申请文件提示性公告”误当成正式发行公告，现已加入排除条件。

## 修正后的管线

1. 监控命中同意注册公告后，检索并下载同一公司的募集说明书注册稿。
2. 从注册稿提取注册额度上限和公告时点总股本，并用行情数据源的股本快照进行交叉核对。
3. 获取最近可用交易日收盘价和历史行情；主行情接口失败时自动使用备用接口。
4. 由 Python 脚本确定性计算每股理论配债额、每 100 股理论可配面值、含权率、理论与保守稳一手股数、资金占用、近期涨跌/波动和五档盈亏平衡跌幅。
5. 只有 `calculation.status=complete` 才允许调用分析和发送；模型不得重算数字，邮件中的计算表由运行器直接注入。
