# 可转债配债混合监控

这个工作流把每日固定工作和事件日分析分开：

- 每个工作日 08:30 由本地 Python 脚本判断 A 股交易日；
- 纯脚本检索上交所、深交所、巨潮资讯、证监会官网；
- 每条结果都记录命中/排除理由，只有全部关键来源成功时才允许发“昨日无新公告”；
- 无新增时通过现有 QQ SMTP 私有配置中的收件人列表直接发送，不调用模型；
- 发现目标公告时下载原始文件、建立证据包，然后才调用 Codex；同一天无论几家公司都只调用一次模型；
- 正式发行文件确认新债简称、申购代码和申购日后，先写入本地提醒队列；申购日 08:50、09:50 由独立计划任务各发送一次结构化提醒，纯程序运行、不调用模型；
- 独立计划任务在工作日 09:15 查询上交所、深交所一手公告，在中签结果公告日或可转债上市日发送结构化出签/上市提醒，纯程序运行、不调用模型；
- 注册阶段会自动补齐募集规模上限、总股本和最近交易日收盘价，并由脚本完成含权率、稳一手股数、资金占用和压力测试计算；
- Codex 只负责解释公告与脚本计算结果，可信计算表由运行器注入邮件；事件运行器优先使用全局新版 CLI，内置 0.165.0 作为兜底，并只在模型兼容错误时切换显式候选模型；未成功发送前不把事件标为已报告。

## 质量控制

`raw/` 保存各官方接口原始响应，`classification_audit.json` 保存每条公告的判定理由，`evidence/` 保存事件证据包和下载文件，`reports/` 保存实际邮件正文。这些文件让纯脚本结果可以与模型逐日回放对照。

如任一关键来源失败，系统发送“监控异常”，不会把网络失败写成“无新增”。

## 申购日双提醒

`可转债配债-申购提醒` 是独立 Windows 计划任务，工作日 08:50、09:50 以及当前用户登录时检查 `subscription_reminders.json`。邮件沿用既有私有收件人配置，标题为 `【可转债申购】请今天申购新债：<新债简称>`，正文列出申购代码、新债/正股基本信息、行业、主营、公司特定题材概念和正式文件链接。

两个批次分别持久化且正文不同，同一批次重试仍保持完全相同；SMTP 成功后才标记完成。错过触发时只在申购日 15:00 前补发，跨日不补发；若登录后独立提醒任务先空跑、主监控后入队，主监控会立即再做一次到期批次补发。日常任务只读取本地可信队列，不扫描证据、不联网或调用模型；可用 `Run-SubscriptionReminder.ps1 -DryRun -AsOf <北京时间>` 做无发送预演，用 `py monitor.py --rebuild-subscription-reminders` 强制重解析已有正式发行 PDF 并回填未来队列。修订公告会使同事件的旧日期/旧代码变体作废，避免重复提醒。

## 出签与上市提醒

`可转债配债-出签上市提醒` 是独立 Windows 计划任务，工作日 09:15 以及当前用户登录时运行 `Run-BondLifecycleReminder.ps1`。它直接查询上交所、深交所发行人公告，只接受经过 HTTPS 官方域名、最终跳转、PDF 签名、SHA-256、标题和正文类型共同验证的原文；不依赖 08:30 主监控、申购任务或模型。

出签只接受网上中签结果、中签号码或摇号中签结果类公告，排除中签率与优先配售结果；标题为 `【可转债出签】<新债简称>`，正文提醒登录券商查看是否中签并准备缴款。上市只接受可转换公司债券上市公告书，必须从正文确认上市日；标题为 `【可转债上市】<新债简称>`，正文提醒确认持仓并盯盘首日。两类邮件均列出债券、正股、关键日期、发行与转股信息、行业、主营、题材和官方链接。

队列按事件类型、新债身份和目标日期幂等，按公告先后应用更正日期，旧记录不会反向覆盖新记录；首次发送前冻结正文，SMTP 成功或重复投递确认后才记完成，多债之间相互隔离。首次扫描回看 90 天，此后保留 3 天重叠；分页会核对官方总数并在重复页或截断时拆分日期，深交所按每页 50 条完整翻页。上市日首次发送前刷新正股收盘价。09:15 后只在当日 15:00 前补发，跨日不补发。可用 `Run-BondLifecycleReminder.ps1 -DryRun -AsOf <北京时间>` 做无发送回放。私有队列、锁和状态文件均不进入 Git。

三个计划任务都使用当前 Windows 用户身份，允许电池供电时启动并在切换到电池后继续运行；均启用 `StartWhenAvailable`、单实例及失败后每 10 分钟最多重试 3 次。

## 注册待发行存量候选池

每个成功交易日日报都会在原有公告核验内容后追加“已同意注册、尚未正式发行”的存量表。注册事件进入台账，正式发行事件当天退出；首次运行从巨潮资讯历史公告回填，之后每日增量更新并每 7 天全量复核一次。注册批复按 365 天有效期管理，逾期且未发行的项目不再作为可执行候选展示。

表格按“注册后累计涨幅”从低到高排序，并显示：

- 股票简称和代码；
- 细分行业与主营业务合并为一列、一个单元格，行业和主营业务上下两行展示，两项各不超过 10 个字符；
- 每百元正股对应的理论含权金额及含权率；
- 上一交易日收盘价相对正式发行前参考转股价下限的位置（百分比保留 0 位小数）；
- 同意注册公告日期和已过交易日；
- 从注册公告日收盘至上一交易日收盘的前复权累计涨跌；
- 最新收盘价、近 10 个交易日涨跌、距注册后最高收盘价的回撤。
- 估算配售 1 手（10 张）所需理论股数 N0，并四舍五入显示到个位数。

累计涨跌、短期涨跌和回撤使用前复权日线，避免分红送转造成虚假跳空；最新价仍对应上一交易日实际收盘。表格是正式发行前的理论估算，发行公告披露后应改用实际发行规模和每股优先配售额。

## 注册阶段数据与完整性闸门

- 募集规模：从巨潮资讯的募集说明书注册稿中提取，并保留原始 PDF；
- 总股本：以注册稿披露的股本快照为主，并与行情数据源的最新股本交叉核对；
- 收盘价与波动：读取最近可用交易日行情，主数据源失败时切换备用行情源，并把原始 JSON 存入证据目录；
- 确定性计算：计算每股理论配债额、每 100 股理论可配面值、理论含权率、理论/保守稳一手股数、所需正股资金和不同转债涨幅下的正股盈亏平衡跌幅；
- 完整性闸门：注册阶段任一关键字段缺失或计算状态不是 `complete` 时，事件分析脚本停止发送，不再生成“无法计算”的低价值邮件。

已报告事件仅允许在 dry-run 中用 `--replay-reported` 重放，用于预览和回归验证，不会污染正常去重状态。

完整产品口径见 `../../docs/可转债配债自动日报产品规格说明书.md`，版本变化见 `../../docs/可转债配债自动日报更新记录.md`。
